# Term 2 Planner — กำหนดเนื้อหาคณิตเทอม 2 รายห้อง

วันที่: 2026-10-28 · สถานะ: รอผู้ใช้ตรวจ

## 1. เป้าหมาย

ผู้ดูแล (ผู้ใช้คนเดียว) กำหนดเนื้อหาคณิตศาสตร์เทอม 2 ปีการศึกษา 2569 ให้แต่ละห้องเรียน
โดยดูจากจุดที่ห้องนั้นสอนจบในเทอม 1 แล้วส่งออก **ภาพ PNG หนึ่งภาพ** สรุปว่าครูทุกคนต้องสอนอะไรในเทอม 2

**สำเร็จเมื่อ:** ทุกห้องมีครูที่ถูกต้อง มีจุดจบเทอม 1 และมีรายการเรื่องเทอม 2 ที่ผู้ใช้ยืนยันแล้ว
และผู้ใช้กดบันทึกภาพสรุปบน iPhone/iPad ได้ภาพที่อ่านชัด

### สิ่งที่ผู้ใช้กำหนด
- ผู้ใช้ใช้คนเดียว ครูไม่ได้เข้าเว็บ (ครูได้ดูจากภาพ PNG)
- ผู้ใช้เลือกเนื้อหาเทอม 2 เองทั้งหมด ระบบไม่คำนวณเรื่องที่ค้างให้อัตโนมัติ
- เติมเนื้อหาเทอม 2 เริ่มต้นจากชีต1 (ชุดอ้างอิงปี 68) ไว้ก่อน แล้วผู้ใช้แก้ต่อ
- เป็น Artifact บน claude.ai
- สไตล์มินิมอล

### ไม่ทำ (YAGNI)
- ไม่มีระบบล็อกอิน ไม่มีหน้าสำหรับครู
- ไม่ซิงก์กับ Google Sheets
- ไม่มีหลายปีการศึกษาหรือหลายเทอมในแอปเดียว
- มีแค่ข้อมูล ม.1 แต่โครงสร้างรองรับการเพิ่มห้องชั้นอื่นได้

## 2. แหล่งข้อมูล

| แหล่ง | ใช้ทำอะไร |
|---|---|
| ภาพ "ชื่อครู และเนื้อหาที่จบล่าสุด" (ผู้ใช้ส่งมา) | **ข้อมูลหลัก** สำหรับจุดจบเทอม 1 และชื่อครู |
| Google Sheet "เนื้อหาที่จบเทอม 1 ปี 2569" › ชีต1 | โรงเรียน/ห้อง/ประเภทวิชา และเนื้อหาเทอม 2 เริ่มต้น |
| › เนื้อหา69 | ลำดับมาตรฐานเทอม 1/เทอม 2 ต่อประเภทวิชา |
| › รายละเอียดวิชา | รายละเอียดย่อยของแต่ละเรื่อง (แสดงเป็นคำอธิบายตอนเลือก) |

ข้อมูลเริ่มต้นเก็บใน `term2-planner/seed.json` (ไม่ฝังในหน้าเว็บ) หลัง publish Claude จะเขียนลงฐานข้อมูลด้วย ArtifactData batch ครั้งเดียว
ถ้าฐานข้อมูลยังว่าง หน้าเว็บจะแสดงข้อความ "ยังไม่มีข้อมูล" ไม่ใช่หน้าพัง

## 3. โมเดลข้อมูล

```
Topic     { id, name, details: string[] }
Sequence  { courseType: "พื้นฐาน"|"เพิ่มเติม"|"เข้มข้น", term: 1|2, topicIds: string[] }
Class     {
  id, teacher, school, room, grade: "ม.1", courseType,
  term1End: { topicId, status: "done"|"partial", note },
  term2TopicIds: string[],          // เรียงตามลำดับสอน
  needsReview: boolean,             // ยังไม่แน่ใจเรื่องครู/ประเภท
  updatedAt
}
```

- ชื่อเรื่องใช้ตามเนื้อหา69/ชีต1 เช่น "สมการ (1)" และ "พหุนาม (1)" ส่วนชื่ออื่นที่หมายถึงเรื่องเดียวกัน
  เช่น "สมการตัวแปรเดียว (1)" ใช้เพื่อจับคู่รายละเอียดวิชาเท่านั้น
- ผู้ใช้เพิ่มเรื่องใหม่ได้ (Topic ที่ไม่มีใน Sequence ใดเลย)

### การเก็บข้อมูล
ใช้ความสามารถ `db` ของ Artifact (ประกาศ `capabilities: {db: {}, downloads: true}`) เอกสารที่เก็บคือ `classes/<id>`, `topics/<id>` และ `meta/config` (ใน `meta/config` เก็บ `sequences`)
ถ้า `claude.use("db")` คืนค่า `null` หน้าเว็บจะแสดงข้อความว่าต้องเปิดใน claude.ai
ห้ามใช้ localStorage เป็นที่เก็บหลัก ทุกครั้งที่แก้ห้องจะบันทึกทันทีทีละเอกสาร (last-write-wins พอเพราะมีผู้ใช้คนเดียว)
ถ้าบันทึกไม่สำเร็จ ให้แสดงแถบแจ้งเตือนพร้อมปุ่ม "ลองใหม่" และเก็บค่าที่แก้ไว้ในหน้า ไม่ทิ้ง

## 4. หน้าจอ

แอปเป็นหน้าเดียว มีแท็บด้านบน 2 แท็บ คือ **ห้องเรียน** และ **สรุป**

### 4.1 ห้องเรียน (รายการ)
- จัดกลุ่มตามครู ห้องที่ยังไม่มีครูอยู่กลุ่ม "ยังไม่ระบุครู" ด้านบนสุด
- แต่ละแถวแสดง โรงเรียน · ห้อง · ประเภท / จุดจบเทอม 1 / "เทอม 2: n เรื่อง"
- ห้องที่ `needsReview` มีจุดสีส้มและข้อความ "ต้องตรวจ" ไม่ใช้สีอย่างเดียวในการสื่อความหมาย
- ตัวกรองด่วนเป็น chip: ทั้งหมด / ต้องตรวจ / พื้นฐาน / เพิ่มเติม / เข้มข้น
- ปุ่ม "+ เพิ่มห้อง"

### 4.2 แก้ไขห้อง (sheet เต็มจอบนมือถือ)
1. **ข้อมูลห้อง**: ครู (dropdown จากรายชื่อเดิม + พิมพ์ชื่อใหม่ได้), โรงเรียน, ห้อง, ประเภทวิชา และสวิตช์ "ต้องตรวจ"
2. **จบเทอม 1 ที่**: ลิสต์เรื่องเทอม 1 ของประเภทนั้นเรียงตามลำดับ แตะเลือกเรื่อง เลือก จบแล้ว/ยังไม่จบ และกรอกช่องหมายเหตุ
   เรื่องก่อนหน้าแสดงเป็น ✓ สีเทา และเรื่องหลังจากนั้นแสดงเป็น "ยังไม่ได้สอน" (แค่แสดงผล ไม่ได้ใช้คำนวณ)
3. **เนื้อหาเทอม 2**: ลิสต์ลำดับที่เลือกไว้ แต่ละแถวมีปุ่ม ↑ ↓ ✕ (ขนาด 44px ขึ้นไป) และปุ่ม "+ เพิ่มเรื่อง" ที่เปิดตัวเลือกเรื่อง
   - ตัวเลือกเรื่องแบ่ง 3 กลุ่ม: "เทอม 1 ที่ยังไม่ได้สอน" / "เทอม 2 มาตรฐาน (ประเภทนี้)" / "เรื่องอื่นทั้งหมด"
     พร้อมช่องค้นหา เรื่องที่เลือกแล้วจะเป็นสีจาง แตะเรื่องเพื่อดูรายละเอียดวิชาแบบย่อ
   - ปุ่ม "คัดลอกจากห้องอื่น…" ใช้แทนที่ลิสต์เทอม 2 ด้วยลิสต์ของห้องที่เลือก (ถามยืนยันก่อน)
4. ปุ่มลบห้อง (ถามยืนยันก่อน)

### 4.3 สรุป
- ตารางจัดกลุ่มตามครู มีคอลัมน์: ครู | โรงเรียน · ห้อง | ประเภท | จบเทอม 1 | เทอม 2
  (คอลัมน์เทอม 2 แสดงเป็นลิสต์ "1. … 2. …" ที่ตัดบรรทัดได้ ความกว้างของภาพจึงคงที่ไม่ว่าจะมีกี่เรื่อง)
- ครูหนึ่งคนอาจมีหลายแถว ชื่อครูแสดงที่แถวแรกของกลุ่ม และมีเส้นแบ่งระหว่างกลุ่ม
- ห้องที่ยังไม่ระบุครูหรือยังต้องตรวจจะมีแถบเตือนเหนือตาราง แต่ยังส่งออกได้
- ปุ่ม **"บันทึกเป็น PNG"**: เรนเดอร์ตารางที่ความกว้างคงที่ 1600px และ scale 2 มีหัวข้อ "เนื้อหาคณิตศาสตร์เทอม 2 ปีการศึกษา 2569" และวันที่
  - เมื่อเสร็จจะเปิดภาพในหน้าต่างพรีวิว ผู้ใช้บน iPhone/iPad กดค้างที่ภาพเพื่อ "บันทึกลงรูปภาพ" ได้
    และมีปุ่ม "ดาวน์โหลด" ที่เรียก `downloads.save({filename: "term2-2569.png", data: blob})` (ซ่อนปุ่มเมื่อ capability นี้เป็น `null`)

## 5. ดีไซน์ (ui-ux-pro-max: Minimalism & Swiss Style)

- **ฟอนต์**: IBM Plex Sans Thai (400/500/600) จาก Google Fonts ขนาดตัวอักษรพื้นฐาน 16px และ line-height 1.6 (ภาษาไทยมีสระบน-ล่าง จึงต้องการระยะบรรทัดมากกว่าปกติ)
- **สี**: พื้นหลังเกือบขาว/เทาอ่อน การ์ดขาว ตัวอักษรเทาเข้ม ใช้สีเน้นสีเดียวคือ teal (#0F766E บนพื้นขาวได้ contrast ≥ 4.5:1)
  และสีส้มสำหรับ "ต้องตรวจ" เท่านั้น ทุกสีกำหนดเป็น token บน `:root` และมีโหมดมืด
- **ระยะห่าง**: สเกล 4/8/12/16/24/32 ใช้เส้นขอบบาง 1px แทนเงา ไม่มี gradient และไม่ใช้ emoji เป็นไอคอน (ใช้ SVG แบบ inline)
- **การโต้ตอบ**: เป้าหมายการแตะขนาด 44×44px ขึ้นไป เห็น focus ring ชัด transition 150–200ms และปิดแอนิเมชันเมื่อ reduced-motion
- **เลย์เอาต์**: mobile-first ไม่มี horizontal scroll ที่ความกว้าง 375px (ตารางสรุปเลื่อนแนวนอนได้เฉพาะภายในกรอบของตาราง)
  บน iPad หน้าแก้ไขห้องเป็นแผงด้านขวา

## 6. เทคนิค

- vanilla JS แบบ ES module ไม่มี build step: `index.html` (โครงหน้า + CSS), `app.js` (UI + db), `logic.js` (ฟังก์ชันล้วน ไม่แตะ DOM)
  ไฟล์ทั้งหมด publish เป็น Artifact เดียวผ่าน `files`
- ส่งออก PNG ด้วย html2canvas 1.4.1 (cdnjs) และรอ `document.fonts.ready` ก่อนเรนเดอร์
- ตรรกะที่เป็นฟังก์ชันล้วน (จัดกลุ่มตามครู, แบ่งกลุ่มในตัวเลือกเรื่อง, สลับลำดับ, seed→batch) อยู่ใน `logic.js` ทดสอบด้วย `node --test`
- ซอร์สเก็บใน repo ที่ `term2-planner/index.html` และ publish เป็น Artifact จากไฟล์นี้

## 7. การทดสอบ

- `node --test` สำหรับ `logic.js` และการตรวจความถูกต้องของ `seed.json`
- สคริปต์ Playwright (`term2-planner/tests/ui.test.mjs`, ใช้ Chromium ที่ติดตั้งไว้แล้ว) เปิดหน้าผ่าน static server ในเครื่อง พร้อม mock `window.claude` (db + downloads แบบ in-memory) แล้วทดสอบดังนี้
  - db ว่าง → แสดง "ยังไม่มีข้อมูล"
  - เพิ่ม/สลับ/ลบเรื่องเทอม 2 แล้วข้อมูลถูกบันทึกลง db
  - คัดลอกจากห้องอื่น
  - ปุ่ม PNG ได้ dataURL ของภาพที่มีความกว้างถูกต้อง
  - ภาพหน้าจอที่ 375px และ 1024px ไม่มี horizontal scroll ระดับหน้า
- ตรวจด้วยตาจากภาพ PNG ที่ส่งออกว่าข้อความภาษาไทยไม่ซ้อนหรือถูกตัด

## 8. ข้อมูลเริ่มต้น (ต้องให้ผู้ใช้ตรวจ)

ห้องที่มี ⚠ คือห้องที่ไม่แน่ใจว่าเป็นของครูคนไหนหรือประเภทอะไร เพราะชื่อครูในภาพต้นฉบับไม่ได้อยู่บรรทัดแรกของกลุ่มเสมอ ห้องเหล่านี้จะถูกตั้ง `needsReview = true`

- **ไฟล์:** "สรุปเนื้อหารายครู เทอม 1-2 ปี 2569" (`1SFIS0R62vjTSnPIYoBVLcEw4-rKZJm6psjAdRca_CyU`) ใช้แท็บใหม่ `ห้องเรียน`, `เรื่อง` และ `ลำดับมาตรฐาน`
  แท็บ `Untitled` เดิมยังเก็บไว้ ไม่ได้แก้ไข
- **รูปแบบแถว:** ใช้ชื่อเรื่องแทนรหัส จึงอ่านและแก้ในชีตได้โดยตรง ถ้าในชีตพิมพ์ชื่อเรื่องที่ไม่มีในแท็บ `เรื่อง` จะใช้รหัส `name:<ชื่อ>` แทน
  คอลัมน์ของแท็บ `ห้องเรียน` คือ `รหัส | ครู | โรงเรียน | ห้อง | ประเภท | จบเทอม 1 | สถานะ | หมายเหตุ | ต้องตรวจ | แก้ล่าสุด | เทอม 2 เรื่องที่ 1-20`
- **การอ่าน:** ใช้ capability `mcp` กับ connector "Google Sheets" ผ่าน `watchTool(get_values)` ที่ดึงใหม่ทุก 30 วินาที
  มีปุ่ม "รีเฟรช" และดึงใหม่ทุกครั้งที่กลับมาที่แท็บ
- **การเขียน:** ก่อนเขียนจะอ่านคอลัมน์ A เพื่อหาแถวตามรหัสห้อง แล้วใช้ `update_values` แก้แถวนั้น ถ้าไม่พบแถวจะใช้ `append_values` เพิ่มแถวใหม่
  การลบห้องคือการล้างแถวนั้นให้ว่าง การแก้ที่บันทึกแล้วจะแสดงบนจอต่อจนกว่าการอ่านชีตครั้งถัดไปจะเห็นค่านั้น นานสุด 60 วินาที

  - `server_not_connected`: ให้เพิ่ม connector
  - `approval_required`: แสดงปุ่มอนุญาต ซึ่งเรียก `callTool` 1 ครั้ง
